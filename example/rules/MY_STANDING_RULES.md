# My standing rules

> FICTIONAL. Bob, every employer, every project, every date and every number in this file are invented so the kit can be tried without anyone's real information.

INSTRUCTIONS ONLY - never a content source.

This file ships with the kit as an empty template, so git does track it. Once
you have written personal details here, that is one more reason not to publish
this folder anywhere.

These are MY always-on preferences. Claude reads this before every draft.
The setup interview filled in the first version on 2026-10-13. After that,
whenever I correct the same thing twice, it gets added here so I never
correct it a third time.

## Always include
- Project Management Professional (PMP), current. Written as in
  sources/master_resume.md: "Project Management Professional (PMP) - PMI -
  2020, renewed 2023 and 2026".
- The LinkedIn link and the GitHub link on the contact line.

## Include only when the posting asks for it
- The coding club volunteering: only when the posting mentions mentoring,
  coaching or community.
- ITIL 4 Foundation (2021): only when the posting mentions ITIL or service
  management. Otherwise leave it off.
- AWS Certified Solutions Architect - Associate: never as a current
  certification. It may appear only if a posting asks for AWS, and then only
  with "expired 2020" next to it.

## Never include
- Any employer name other than the invented ones. Employers are always
  "Company N", "Company A" and "Company F", each with its one-line sector
  description.
- The names of the hospitals or the hospital group at Company A.
- The "FICTIONAL" note in the master resume. It is a comment and never prints.
- Any statement that I "led" the PCI DSS audit. I was the developer on it.
- Any statement that I "own" a budget. I track and forecast; the PMO and the
  Head of Delivery approve spend.
- Any statement that I "manage" or "line-manage" project managers. I mentor
  two junior PMs; I have no line reports at Company N.
- Any claim that I am SAFe certified. I completed a two-day SAFe for Teams
  course in 2024 and did not sit the exam.
- Kubernetes. Never used.
- Every item on the "Do not state - master list" in sources/bullet_bank.md
  (project costs, defect counts, contract sizes, savings, student or user
  counts, change request numbers, time-of-day details).
- Street address, date of birth, photo, ID numbers, referees.

## Exact wording for sensitive items
- The Company A migration slip, always: "went live six weeks after the
  original date, on the re-baselined date agreed with the customer".
- The career change, always: "seven years as a developer and tech lead before
  moving into project management".
- The three roles at Company A are listed as three separate roles under one
  employer heading, each with its own dates. Never merged into one role.

## Style
- Plain verbs. No "spearheaded", "orchestrated", "leveraged", "championed".
- No year counts in the summary ("15 years of..."). Dates carry tenure. The
  one exception is the fixed career-change line above, which names seven
  years.
- Name the system, the customer type and the constraint. Not "company-wide
  initiatives".
- Never deliberately introduce a typo or error.

## Page and format
- Set in `config.json`: Letter, Calibri 11 point, two pages.
- Two pages is the target. Never a third page.
